# 通讯录需求与验收标准（Phase A0）

## 1. 文档目的

本文档定义 EE308 Extreme Programming 双人课程项目“轻量级通讯录”的产品范围与可验收行为。本文描述的是后续阶段需要实现的需求，不代表相关功能已经完成。

项目采用 Vue 3、TypeScript 和 Vite 构建纯前端单页应用；Excel 文件处理使用项目已安装的 ExcelJS。共享数据模型以 `src/types/contact.ts` 为准。

## 2. 用户与核心对象

- 目标用户：在单一浏览器中管理个人联系人资料的用户。
- 核心对象：`Contact`，包含姓名、公司、备注、收藏状态、多个联系方式及创建/更新时间。
- 联系方式：`ContactMethod`，类型限定为 `phone`、`email`、`social`、`address` 或 `other`，并包含标签和值。
- 时间字段以 ISO 8601 字符串保存；标识符在当前数据集中必须唯一且稳定。

## 3. 功能需求与验收标准

### FR-01 新增联系人

用户可以创建联系人并录入基本信息与零个或多个联系方式。

验收标准：

1. 用户可以输入姓名、公司、备注、收藏状态和多个联系方式。
2. 姓名为必填项；只有通过校验的数据才能保存。
3. 保存后生成唯一联系人 `id`、`createdAt` 和 `updatedAt`，并立即出现在联系人列表中。
4. 取消操作不产生新联系人，也不改变已有数据。

### FR-02 编辑联系人

用户可以修改已有联系人的基本信息、收藏状态和联系方式。

验收标准：

1. 编辑界面能回填被选联系人的全部现有数据。
2. 保存后保留联系人 `id` 和 `createdAt`，更新 `updatedAt`。
3. 保存结果在列表、详情和刷新后的持久化数据中一致。
4. 取消编辑不改变原联系人。

### FR-03 删除联系人

用户可以删除指定联系人。

验收标准：

1. 删除前提供明确的确认步骤，降低误删风险。
2. 确认后仅删除目标联系人，并同步更新持久化数据。
3. 取消确认时数据不发生变化。

### FR-04 搜索联系人

用户可以通过文本快速缩小联系人范围。

验收标准：

1. 搜索至少覆盖姓名、公司及各联系方式的 `label` 与 `value`。
2. 搜索忽略英文大小写和输入首尾空白。
3. 清空搜索条件后恢复当前筛选范围内的全部联系人。
4. 无匹配项时显示清晰的空状态，而不是报错或空白页面。

### FR-05 本地数据持久化

联系人数据在无后端条件下保存在浏览器本地。

验收标准：

1. 新增、编辑、删除、收藏和导入后，持久化数据同步更新。
2. 同一浏览器刷新或重新打开页面后，已保存数据仍可恢复。
3. 首次使用或存储为空时正常显示空状态。
4. 遇到不可解析或结构不合法的存储数据时，应用不崩溃，并给出可理解的错误反馈或安全降级。

### FR-06 收藏与收藏筛选

用户可以收藏或取消收藏联系人，并仅查看收藏联系人。

验收标准：

1. 用户可从可见的联系人操作入口切换收藏状态。
2. 收藏状态变更后立即反映在界面和持久化数据中。
3. 开启收藏筛选时仅显示 `favorite === true` 的联系人。
4. 收藏筛选可与搜索组合使用；关闭筛选后恢复符合其他条件的联系人。

### FR-07 多联系方式管理

单个联系人可以管理多个电话、邮箱、社交账号、地址及其他联系方式。

验收标准：

1. 每个联系方式包含稳定的 `id`、`type`、`label` 和 `value`。
2. 同一联系人可添加多个同类型或不同类型的联系方式。
3. 用户可动态新增、编辑和删除联系方式。
4. 编辑联系人时，联系方式完整回填且顺序不被无故改变。
5. 具体组件边界和校验规则遵循 `docs/CONTACT_METHODS_CONTRACT.md`。

### FR-08 Excel 导出

用户可以将全部联系人导出为 `.xlsx` 文件，每个联系人占一行，联系方式按实际最大数量动态展开为列组。

验收标准：

1. 导出文件包含固定字段：`id`、`name`、`company`、`note`、`favorite`、`createdAt`、`updatedAt`。
2. 联系方式按序号展开为 `method_1_id`、`method_1_type`、`method_1_label`、`method_1_value`，随后为 `method_2_*`，依此类推。
3. 动态列数以本次导出数据中联系方式的最大数量为准；没有对应联系方式的单元格留空。
4. 每个联系人仅占一行；特殊字符、中文和多行备注在导出后不丢失。
5. 无联系人时仍能导出带表头的有效工作簿，或给出明确的空数据提示。

### FR-09 Excel 导入与模板

用户可以导入符合模板的数据，并可下载可填写的 `.xlsx` 模板。

验收标准：

1. 模板包含固定字段和至少一组空的 `method_1_*` 联系方式列，并说明允许的 `type` 值。
2. 导入器识别连续编号的 `method_N_id/type/label/value` 列组，支持任意合理数量的联系方式。
3. 空的整组联系方式不生成记录；部分填写、未知类型或其他不合法的列组产生可定位到行/列的反馈。
4. 必填字段、布尔值、时间和标识符经过校验；导入不会因单个错误静默损坏现有数据。
5. 导入前向用户展示结果或确认信息，至少说明有效记录数和错误记录数。
6. 应用导出的文件无需手工改列即可重新导入，并保持联系人基本字段、收藏状态、时间字段、联系方式内容及顺序，实现完整数据往返。
7. 对缺失 `id` 的新记录，导入时生成唯一标识符；已有 `id` 的冲突处理策略必须在确认导入前明确告知用户。

### FR-10 错误反馈

验收标准：

1. 表单校验错误显示在相关字段附近，并说明修正方式。
2. 文件格式错误、导入校验错误、存储失败等操作级错误有明确反馈。
3. 错误消息不泄露堆栈或内部实现细节，且不以静默失败代替反馈。
4. 失败操作不得导致现有有效数据被部分覆盖或意外清空。

### FR-11 响应式与可用性

验收标准：

1. 主要流程在常见手机宽度（从 320 px 起）及桌面视口下可操作，无必须依赖水平滚动的核心控件。
2. 表单控件有可见标签；键盘可以到达主要操作，焦点状态清晰。
3. 删除、导入等高影响操作与普通操作在文案或视觉上可区分。
4. 加载、空数据、无搜索结果和错误状态均有明确展示。

### FR-12 基本测试

验收标准：

1. 使用项目已安装的 Vitest；Vue 组件测试可使用 Vue Test Utils 和 jsdom。
2. 至少覆盖联系人数据的新增/编辑/删除、搜索与收藏筛选、持久化序列化/恢复、联系方式校验、Excel 导入解析和导出列展开中的核心规则。
3. 测试必须可重复运行，不依赖网络、执行顺序或开发者本机残留数据。
4. 合并前类型检查、自动化测试和生产构建均通过。

## 4. Excel 数据契约

固定列保持上述英文列名，以便稳定往返。联系方式列使用从 1 开始且连续的编号：

| 列名 | 含义 |
| --- | --- |
| `method_N_id` | 联系方式唯一标识；新导入数据可留空并由应用生成 |
| `method_N_type` | `phone` / `email` / `social` / `address` / `other` |
| `method_N_label` | 用户可读标签，例如“工作手机”或“GitHub” |
| `method_N_value` | 实际电话号码、邮箱、账号、地址或其他内容 |

导入导出实现不得用逗号、分号等不可靠分隔符把多个联系方式压缩进一个单元格。未来若需改变列名、类型枚举或往返规则，应先更新本需求、共享 TypeScript 类型和相关测试，再由两位成员共同评审。

## 5. 非功能约束

- 保持轻量级纯前端架构，与现有 Vue 3 + TypeScript + Vite 技术栈一致。
- 类型检查采用项目 TypeScript 配置；生产构建采用 Vite。
- 不将敏感信息写入日志；本地持久化的限制应在产品说明中保持透明。
- 代码应遵循 `docs/CODING_STANDARDS.md`，共享契约变更需要双方评审。

## 6. 非目标

本阶段及当前产品范围明确不包含：

- 用户注册、登录、鉴权或账号体系；
- 后端 API、服务器部署或服务端业务逻辑；
- MySQL 或其他服务端数据库；
- 多用户、跨设备实时同步或冲突合并。

## 7. 完成定义

某项功能只有在对应验收标准得到验证、相关测试通过、类型检查与生产构建通过，并经过代码审查后，才可标记为完成。Phase A0 仅建立需求、数据契约与协作规范，不表示上述产品功能已实现。
